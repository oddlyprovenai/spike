# Build Your First Custom Specialist

Language: [Español](../es/first-specialist.md) | **English** · [Guide Index](README.md)

![Specialists and Custom Pack Configuration](../images/specialists.png)

## What it does

Lets you extend SPIKE beyond the 13 built-in domains by creating your own domain specialist — complete with a dedicated system prompt, an explicit tool allowlist, weighted Spanish and English lexical-router keywords, specialist-scoped reference documents, and a companion `SKILL.md` workflow — and export the result as a secret-free `.zip` Specialist Pack (`format: "spike-pack"`, `version: 1`). Advanced contributors on Apple Silicon can optionally propose a pre-registered LoRA adapter recipe gated by SPIKE's license allowlist and statistical anti-forgetting rules.

## Step-by-step usage

### Part 1 — Create a custom specialist profile & pack (2 minutes, no training required)

1. **Design the specialist definition (`custom_specialists` entry):** give it a lowercase `id`, a clear `system_prompt`, the minimal `tools` it actually needs, and whole-word `keywords` weighted on SPIKE's `2.0`-threshold router scale (`4` = unambiguous domain jargon, `3` = strong domain term, `2` = routes alone unless outscored, `1–1.5` = weak cue that only counts alongside another term):

```json
{
  "id": "logistics",
  "name": "Spike Logistics",
  "domain": "Supply chain, inventory and freight operations",
  "description": "Calculates safety stock, reorder points, lead-time buffers and freight terms from workspace spreadsheets.",
  "adapter": null,
  "adapter_status": "none",
  "sensitive": false,
  "tools": ["calculator", "read_file", "data_describe", "data_sql", "ask_user"],
  "keywords": {
    "incoterms": 4,
    "fob": 3,
    "albarán": 4,
    "albaran": 4,
    "reorder point": 4,
    "punto de pedido": 4,
    "safety stock": 4,
    "stock de seguridad": 4,
    "lead time": 3,
    "inventario": 2
  },
  "system_prompt": "You are Spike Logistics. Compute reorder points, safety stock and freight terms using calculator or data_sql instead of mental arithmetic. State assumptions clearly and never invent carrier rates."
}
```

2. **Add it in Settings or via loopback API:** open **Settings → Specialists** to add your custom specialist (or merge it into `custom_specialists` via `PATCH /api/settings` on `127.0.0.1:8740`). Because `adapter_status` is `"none"`, SPIKE honestly displays it as an instruction profile on the shared base model (or bound external provider).
3. **Pair it with a validated `SKILL.md` procedure:** place a UTF-8 `SKILL.md` inside `~/.spike/skills/inventory-reorder-audit/SKILL.md` and check it offline with `spike skills validate`:

```markdown
---
name: inventory-reorder-audit
description: Audit SKU lead times, demand variance, and reorder thresholds with SQL before recommending stock buffers.
license: Apache-2.0
---
# Inventory Reorder Audit

1. Inspect schema and row counts first with `data_describe`.
2. Compute mean demand, standard deviation, and reorder point via `data_sql` or `calculator` — never estimate numbers in prose.
3. Flag SKUs with negative or missing lead times before summarizing findings.
```

4. **Attach specialist-only reference notes (optional):** upload domain SOPs or formulas that **only** this specialist recalls via **Settings → Specialists** or `POST /api/specialist-documents` (`{"specialist": "logistics", "filename": "incoterms-notes.md", "text": "..."}`).
5. **Share or back up as a Specialist Pack:** click **Export pack** (`GET /api/pack/export`) to download a single `.zip` containing `pack.json` and `skills/<name>/SKILL.md` (validated against [`specialist-pack.schema.json`](../../schemas/specialist-pack.schema.json)). Connector credentials, headers, and environment variables are stripped automatically. Import on another machine via `POST /api/pack/import`.

### Part 2 — Optional LoRA adapter pipeline (Apple Silicon contributors)

If an instruction profile is not enough and you want to train a `~42 MB` GGUF LoRA adapter (`training/`):

1. **Verify dataset licenses first (`training/datasets.yaml`):** SPIKE's gate (`training/spike_train/licenses.py`) accepts **only** permissive open licenses (`Apache-2.0`, `MIT`, `BSD`, `CC-BY-4.0`, `CC0`, `ODC-By`). **Never use outputs generated by Claude, GPT, Gemini, or Llama 3.1** (forbidden by upstream terms and rejected by `prepare.py` and `model_card.py`).
2. **Pre-register the acceptance gate before training (`training/configs/<id>.yaml`):** write your `hypothesis`, `primary` domain suite (`min_gain_points: 3.0`, `max_p_value: 0.05`), and `regression` suite (`general`, `max_drop_points: 1.5`) *before* running a single training step.
3. **Decontaminate, train with self-replay, and sweep:** `prepare.py` removes 13-gram overlaps against all evaluation sets; `fix_forgetting.py` and `sweep_checkpoints.py` evaluate candidate checkpoints and LoRA scales on `*-select` splits first and run the held-out acceptance suite once.
4. **Install only passing adapters:** `spike adapters install` verifies the evaluation receipt and SHA-256 checksum and refuses any adapter that failed its gate (see [../../TRAINING.md](../../TRAINING.md) and [../../SPECIALISTS.md](../../SPECIALISTS.md)).

## Real limits

- Custom specialists created in Settings or imported via a pack run as **prompt profiles** (`β` / `none`) on the base model or configured API provider; SPIKE never labels a custom specialist as a trained adapter without a verified acceptance receipt (`spike/specialists/acceptance/<id>.json` or active Evolution record).
- Lexical router keywords match whole words (case- and accent-insensitive); inflected plurals or verb forms should be listed explicitly if you want ~1 ms zero-LLM routing.
- How well the 4B local model follows a user-written custom `SKILL.md` or custom specialist prompt is **not measured** until you add at least 3 local evaluation checks in **Settings → Evolution** (`spike evolve check`); see [../../STATUS.md](../../STATUS.md).

## How to verify

- Validate custom skills offline: `.venv/bin/spike skills validate`.
- Run the executable test for this guide (loads the JSON specialist above, routes EN/ES queries, and round-trips a `.zip` pack against the v1 JSON Schema): `.venv/bin/python -m pytest -q tests/test_user_docs_u4.py tests/test_packs_reliability.py tests/test_specialists_status.py`.
